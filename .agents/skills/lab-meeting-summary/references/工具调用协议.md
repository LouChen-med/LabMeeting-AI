# Windows 宿主工具调用协议

本协议用于把同一套工具接入不同 Windows AI 软件。差异在宿主的工具接口、输出限制和图像展示能力，不表示已支持其他操作系统。先读本文件，再将能力映射到宿主实际提供的工具；不要凭下文伪代码虚构 API。

会议处理只读取原视频和本地模型，音频、转写、图片及计时均留在内存。仅最终纪要 MD 写盘。不得以临时脚本、stdout 重定向、Tee、日志、截图或缓存文件绕过这一约束，也不能先生成再删除。

本工具的约束范围是启动方式及工具生成的会议文件：脚本尽早禁用Python字节码/CUDA缓存、启用HF离线模式，并以Python audit hook拦截文件写入尝试，遇到此类尝试直接失败。宿主也不得另存转写、截图或使用磁盘spool。脚本不能控制AI应用自身会话数据库、系统分页或未暴露audit事件的原生DLL写入；本轮真实短测及目录监控的已测范围见[方案依据](方案依据.md)，不将本工具的内存处理夸大成整个操作系统无写入。

## 1. 先确认四项必需能力

| 能力 | 宿主必须实际做到 | 不具备时的动作 |
|---|---|---|
| 本地文件访问 | 读取工具代码、模型和用户指定视频；仅写最终 MD | 说明不可访问的路径并停止依赖该路径的步骤 |
| 本地子进程 | 直接启动已核实的Conda环境绝对解释器，取得句柄、stdout、stderr 和最终退出码；不生成临时启动脚本 | 不把云端执行容器当成本机，不继续声称已处理视频 |
| 跨调用内存 | 在工具截断前捕获完整 stdout，保留未结束行、事件和后续读取 cursor；不另存转写或使用磁盘spool | 无法保证完整捕获时，先适配工具；不得先运行整场再补救 |
| 内存图像内容 | 解析 JSON data URL，将 JPEG 字节交给宿主支持的 image 内容入口，不另存截图 | 可以继续有证据的音频分析，但须明确未做画面复核；不得声称已看图 |

模型能读文字不代表具备这些能力。不同软件须分别核对；不硬绑某一品牌的函数名、CLI 或图片显示 API。安装和首次模型下载见首次配置参考，不在每次会议处理时重复。

## 2. 调用顺序和判定

| 步骤 | 输入与操作 | 返回内容 | 成功条件 | 失败动作 |
|---|---|---|---|---|
| 1 | 核对宿主能力、现有配置与输入输出路径 | 可用工具及真实路径 | 读取本机视频，最终 MD 目标已明确 | 先说明缺口，不猜路径或安装依赖 |
| 2 | 由已核实Conda环境的独立解释器启动 `stream` | 进程句柄、stdout、stderr | 无临时启动脚本，进程启动且可持续接收完整字节流 | 保留内存诊断，停止依赖后续转写 |
| 3 | 连续接收并解析全部 JSONL | `audio_ready`、多批 `segments` | 字节、行、批次均未丢失，顺序正确 | 已截断或丢失则标明读取范围，不能声称整场完成 |
| 4 | 消费最后一批，等待进程结束 | 唯一 `complete` 和退出码 | 退出 0、段数与范围核对通过 | 缺完成事件、非 0 或核对失败均不算完成 |
| 5 | 完整阅读转写，选少量具体时点 | 内存中的课题索引、歧义和图表时点 | 每一批均已阅读，包含问答尾部 | 未读部分明确待核，不用图片抽样替代 |
| 6 | 调用 `frame-inline` 并渲染内存图像 | 一帧一条 `frame` JSON | 无截断、退出 0、时间及内容可辨认 | 减少帧数或调整宽度；仍不清楚则保留待核 |
| 7 | 综合音频和实际查看的画面 | 最终纪要正文 | 逐人总结有证据，重要内容有视频时间 | 不补姓名、数字、机制或任务承诺 |
| 8 | 将内存中完整正文直接写用户指定的最终 MD | 单一正式交付文件 | 无临时稿、原子写入临时副本或工具备份，文件内容可读 | 已有文件须遵守覆盖授权，不能静默替换 |

每次 shell 都可能是新进程：不共享前次的变量、工作目录、`conda activate` 状态或进程内环境设置。每次提供已核实的固定入口或完整解释器和脚本路径及所需参数。环境仍由Conda管理，但日常命令不用 `conda run`：本机该入口会先创建临时批处理再删除，`--no-capture-output`并不关闭此行为。Skill自带的 `scripts/run.cmd`是经授权保存的持久工具入口，运行时不生成新的批处理，自动加入 `-I -B -u -X utf8`并透传完整CLI参数。

宿主可直接以参数数组启动解释器，避免额外shell；若使用PowerShell，采用无profile、非交互的新进程（`-NoProfile -NonInteractive -Command`），命令从进程参数传入，不写 `.ps1`或批处理，不使用交互历史或转录功能。宿主自己的进程包装和输出/图像工具也不得另行生成会议中间文件。

## 3. 启动转写的完整 PowerShell 模板

以下项目、Conda环境解释器和DLL路径均为当前机器已核实的路径。其他 Windows 机器须替换为已核实的实际路径，不要原样猜用；DLL目录可以重复传入。

推荐固定入口示例，项目内与全局Skill均可使用；安装全局副本后，将入口路径替换为 `J:\codex\.codex-data\home\skills\lab-meeting-summary\scripts\run.cmd`：

```powershell
& 'C:\Windows\System32\cmd.exe' /d /c '"E:\BRC\Meet\LabMeeting-AI\.agents\skills\lab-meeting-summary\scripts\run.cmd" stream --video "会议视频的实际完整路径.mp4" --model "E:\BRC\Meet\LabMeeting-AI\models\large-v3-turbo" --dll-dir "D:\software\Anaconda\envs\DL\Lib\site-packages\torch\lib" --compute-type int8_float16 --batch-size 2 --beam-size 1 --language auto'
if ($LASTEXITCODE -ne 0) { throw "stream failed: exit $LASTEXITCODE" }
```

项目优先取本次进程的 `LABMEETING_AI_PROJECT`，否则入口从自身目录向上四级寻找仓库，未找到再回退本机项目。用户显式给出项目时需传入该进程变量，不能从全局Skill所在目录推定仓库。解释器可由本次进程的 `LABMEETING_AI_PYTHON`覆盖，均须先核实，不修改系统环境。以下直接解释器模板是等价备用，与固定入口二选一，不重复执行整场：

```powershell
$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
& 'D:\software\Anaconda\envs\labmeeting-ai\python.exe' -I -B -u -X utf8 'E:\BRC\Meet\LabMeeting-AI\labmeeting.py' stream `
  --video 'E:\BRC\Meet\课题组\会议目录\会议视频.mp4' `
  --model 'E:\BRC\Meet\LabMeeting-AI\models\large-v3-turbo' `
  --dll-dir 'D:\software\Anaconda\envs\DL\Lib\site-packages\torch\lib' `
  --compute-type int8_float16 --batch-size 2 --beam-size 1 --language auto
if ($LASTEXITCODE -ne 0) { throw "stream failed: exit $LASTEXITCODE" }
```

宿主以自己的异步子进程工具启动以上命令，再读取同一个进程。`-I`隔离用户site和 `PYTHONPATH`，`-B`禁止字节码写盘，`-u`实时转发输出，`-X utf8`固定UTF-8；无需另外设置会被 `-I`忽略的Python环境变量。不能把“命令已启动”当成转写完成。

整场处理不传 `--limit-seconds`。短测可以显式加 `--limit-seconds 120`，但其完成事件会标为 `limited`，只能说明该片段的验证结果。

`stream` 本地解码音轨为保留视频时间轴的 16 kHz 单声道数组，随后执行 CUDA ASR；不会解码整段 4K 画面。脚本在依赖导入前配置MKL、禁用CUDA缓存、启用HF离线并安装Python层文件写入拦截。入口在当前进程加载本环境 `sys.prefix\Library\bin`，不依赖 `activate`、不修改系统PATH；`--dll-dir`也只影响本次Python进程。原生DLL的验证范围见方案依据，不能由audit hook推断所有原生写入均受控。

默认 `--language auto`映射 `language=None`、`multilingual=True`、`task=transcribe`；每个VAD音频块（约30秒）选择主语言提示，支持中英文交替，不是逐词或最终字幕段的语言检测。`zh`/`en`固定提示并关闭分块切换，均不翻译；同一块内的混合术语仍须复核。当前真实短测为中文，尚无中英人工标注准确率验证。

## 4. stdout 是 JSONL，工具返回块不是事件边界

`stream` 按以下顺序输出，每个完整事件占一行：

1. `audio_ready`：字段 `audio` 包含处理音频 `duration_seconds`、`source_duration_seconds`、采样率及时间轴信息。
2. `segments`：通常每 100 段一批；尾批可以少于 100 段。字段为 `processed_through_seconds` 和 `segments`。
3. 每段包含数值 `start`、`end`、可读 `time` 及原样 `text`；不要按文本相同就删除段落，重复讨论可能有实质含义。
4. `complete`：包含 `source`、`scope`、`limit_seconds`、`source_duration_seconds`、`audio_duration_seconds`、`count`、`language`、`timings` 和运行设置。`language`是初始语言检测结果，不代表所有音频块均为该语言；`settings`另含 `language_mode`、`multilingual`、`task`用于核对所选模式。

工具可能在一条 JSON 或一个中文 UTF-8 字符中间分块。必须跨读取保留增量解码器与未结束行；同一块也可能含多条事件。只收到最后的完成统计无法替代已丢失的转写。

下面是**抽象伪代码，不是任何宿主的真实 API**。用宿主已存在的子进程、内存和图像工具实现相同语义，不把函数名直接拿来调用：

```text
process = HOST.start_local_process(command, stdout_pipe=True, stderr_pipe=True)
decoder = UTF8_INCREMENTAL_DECODER(errors="strict")
carry = ""; cursor = INITIAL_CURSOR
segments = []; completion = NONE; diagnostics = MEMORY_BUFFER()
while process_not_finished_or_output_remains:
    reply = HOST.read_process(process, after_cursor=cursor)
    REQUIRE reply.output_not_truncated_and_not_lost
    FOR EACH previously_unconsumed_stdout_byte_chunk IN reply:
        carry += decoder.decode(byte_chunk)
        WHILE carry contains newline:
            line, carry = TAKE_FIRST_LINE(carry)
            IF line is not blank: HANDLE(JSON_DECODE(line))
    diagnostics.append(reply.new_stderr)  # 仅内存，不混进 JSONL
    cursor = reply.next_cursor
carry += decoder.decode(EMPTY_BYTES, final=True)
IF carry.strip() is not empty: HANDLE(JSON_DECODE(carry))
REQUIRE process.exit_code == 0 AND completion exists exactly once
REQUIRE len(segments) == completion.count
```

`HANDLE` 对 `segments` 追加原样段；对 `complete` 保存统计；对 `audio_ready` 保存时长。若宿主提供的是已解码字符串，也须确认它已正确跨块处理 UTF-8，再保留未结束行。

使用宿主提供的 cursor、字节偏移或事件序号防止反复接收同一工具输出。没有此机制时，先建立可靠的读取适配。不得按段落文字去重，也不得凭时间戳相同推断工具重复。

完整捕获必须发生在工具的显示截断之前：将大批数据留在宿主内存，分批返回可读文字供当前 AI 阅读。仅调高最终回复字数或模型上下文不能恢复底层已经丢失的输出。不得改为磁盘缓冲。

适配时核实宿主的进程、缓冲和图像工具不会为本次处理另写转写、图片或spool。提供data URL或声称“内存缓冲”并不能单独证明这一点；使用实际工具能力，不虚构可关闭缓存的参数。

stderr 用于诊断 CUDA、依赖或解码错误，不能当会议发言；若宿主只能合并 stdout/stderr，必须能可靠区分诊断和事件，否则停止解析并说明限制。

## 5. 证明处理范围，再使用“整场完成”

- `complete.scope` 必须为 `full`，`limit_seconds` 必须为 JSON `null`；`limited` 不能用于整场结论。
- 核对 `complete.source` 的路径、大小与修改时间对应用户指定的原视频，而不是另一个短片。
- 收到的段数必须等于 `complete.count`；保持原顺序，并检查段时间是否合理、是否覆盖已收到的全部事件。
- 对照 `audio_ready.audio.duration_seconds` 与 `complete.audio_duration_seconds`，并结合 `source_duration_seconds` 检查明显缺口。容器和音轨可能略有时长差，不要求毫秒完全一致。
- 第一段或最后一段有静音并不等于漏读；但缺失尾批、问答尾声、完成事件或原始数据时，不能推定已完整阅读。
- 转写耗时来自 `timings`；它不包括当前 AI 完整阅读、画面复核和纪要写出。端到端指标还需计算这些步骤，不能用 ASR 单步冒充。

## 6. 按时间提取少量内存关键帧

先用转写选定课题切换、关键图表或术语歧义的时间。`--times` 接受秒数或 `HH:MM:SS`；脚本按时间排序并合并重复时点。

```powershell
$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
& 'D:\software\Anaconda\envs\labmeeting-ai\python.exe' -I -B -u -X utf8 'E:\BRC\Meet\LabMeeting-AI\labmeeting.py' frame-inline `
  --video 'E:\BRC\Meet\课题组\会议目录\会议视频.mp4' `
  --times 00:05:00 00:32:10 --width 1920
if ($LASTEXITCODE -ne 0) { throw "frame-inline failed: exit $LASTEXITCODE" }
```

每帧一条 JSON：`event="frame"`、`requested_seconds`、`actual_seconds`、`width`、`height`、`data_url`。图像为内存 JPEG；不要把 `data_url` 原文或 base64 文本输出给模型。

宿主应完整捕获、解码 JSON，再把 data URL 或解码后的字节交给自己的 image 内容工具，附上实际视频时间；当前 AI 必须真正收到并查看图像。下面同样是抽象语义：

```text
frame = JSON_DECODE(complete_stdout_line_held_in_memory)
REQUIRE frame.event == "frame" AND frame.data_url starts with "data:image/jpeg;base64,"
HOST.return_image_content(frame.data_url, label=frame.actual_seconds)
```

单次只取少量时点，提前核对宿主的字节、token 和图像数量限制。必须在 base64 进入模型可见的文字结果前完成图像转换。即使仅一帧，也不能接受已经截断的 JSON 或图片字节。

超过输出上限时减少每次帧数，必要时降低 `--width`，而不是写图片文件。降低后文字仍不可辨认、时间明显偏离、页面未完整显示或宿主不支持图片时，相关姓名、数字和图表结论标为待核。

核对返回帧数等于本批不同请求时点数，退出码为 0。引用以 `actual_seconds` 对应的实际时间为准；需要时只查看相邻几秒，不扩大成全视频逐帧分析。

## 7. 停止条件与最终交付

输出被截断或丢失、JSON/UTF-8 无法完整解析、进程非 0、段数或范围核对失败、帧超过宿主上限或必需能力不足时，停止依赖缺失证据的工作，并如实说明已处理、已阅读、已查看的范围。

不得静默切 CPU、另接收费 API、启动第二个总结模型，或重跑整场来掩盖读取失误。先解决具体的工具容量、依赖或授权问题；如确需重跑，明确原因、范围和额外耗时。

此流程无需额外 FFmpeg CLI，也不调用总结 API：PyAV 完成本地解码，当前 AI 直接理解转写和少量图片。最终MD只放会议内容与视频时间索引，不嵌图，不附转写、图片、日志或其他中间文件。完整正文在内存准备好后直接写目标，目标不存在时独占创建；不得使用临时稿、原子写入临时副本或暗自生成备份的文件工具。回读后检查本工具的输出，无残留检查不能证明从未先写后删。
