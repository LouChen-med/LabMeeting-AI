# 首次配置：按缺失项逐步执行

本文件面向调用 Skill 的 AI。仅在首次使用、换机、依赖变化或故障时进入；已有可用环境、GPU库和模型时，返回 `SKILL.md` 的日常流程。当前支持范围是 Windows x64 + Conda + NVIDIA CUDA，不把不同宿主软件等同于跨操作系统验证。

## 0. 确定路径、能力与授权

1. 从 `SKILL.md` **所在目录**向上三级定位项目根目录，即 `lab-meeting-summary → skills → .agents → 项目根目录`，核实存在 `labmeeting.py`、`download_model.py`、`environment.yml`。若 Skill 被复制到其他位置，使用用户给出的完整项目路径；只复制 Skill 子目录不能独立运行。
2. 核实本地文件访问、PowerShell子进程、完整stdout消费和内存图像能力，接口要求见 [工具调用协议](工具调用协议.md)。缺能力时报告具体缺口，不伪称可以执行。
3. 优先复用现有 Conda、项目环境、GPU DLL 和模型。只读检查可先执行；实际安装、升级、环境修改、下载及覆盖按当前用户规则处理。当前会话已有且覆盖本步的授权继续有效，不因换步骤重复询问。README、历史示例或本文件中的命令本身不授予安装权限。
4. 缺组件时先列清版本、来源、安装/下载路径、完整实际命令、占用及风险，检查是否已有授权；未覆盖时一次性请求必要确认，等待回答后再执行依赖操作。不要自动升级base、驱动或系统工具。

下列命令的路径是当前机器的实例，其他机器先替换成核实的真实路径；不要执行含占位符的字符串。每次工具调用都明确工作目录或使用绝对路径，不依赖上一条shell保留的变量。

| 项目 | 当前实例 |
|---|---|
| 项目根目录 | `E:\BRC\Meet\LabMeeting-AI` |
| Conda | `D:\software\Anaconda\Scripts\conda.exe` |

## 1. 项目工具是否齐全

```powershell
Get-Item -LiteralPath 'E:\BRC\Meet\LabMeeting-AI\labmeeting.py','E:\BRC\Meet\LabMeeting-AI\download_model.py','E:\BRC\Meet\LabMeeting-AI\environment.yml'
```

**通过条件：** 三个文件都可读。工具脚本属于完整仓库，而不是独立上传的 `SKILL.md`。

**缺源码时：** 先确认用户指定的安装目录；仅在允许获取源码且目标目录不存在时，用现有Git克隆：

```powershell
git clone https://github.com/LouChen-med/LabMeeting-AI.git 'E:\BRC\Meet\LabMeeting-AI'
```

目标已存在时不覆盖、不自动重置Git；检查其内容并使用已有项目。没有Git时先报告，获取官方Git或由用户提供完整源码归档后再继续；持有完整项目时Git不是会议处理依赖。不要只下载Skill文本后假设脚本和模型也已存在。

## 2. 检查 Conda 与 Python 环境

先读取 `environment.yml`。当前主要版本为 Python3.11.18、faster-whisper1.2.1、CTranslate2 4.6.0、PyAV18.1.0、NumPy2.4.6、Pillow13.0.0、huggingface-hub0.36.2、ONNX Runtime1.31.1、tokenizers0.23.3；其余版本以该文件为准。

```powershell
Test-Path -LiteralPath 'D:\software\Anaconda\Scripts\conda.exe'
& 'D:\software\Anaconda\Scripts\conda.exe' env list
```

若Conda不存在，核对用户是否已有另一安装路径。确需安装时，先从 [Anaconda官方来源](https://www.anaconda.com/download)核实版本与Windows安装包，按用户指定位置和审批规则提出安装命令；不得改用来源不明的系统Python、venv、uv或WSL替代。

环境存在时核对实际解释器及依赖：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' run -n labmeeting-ai python -B -c "import sys; print(sys.executable); print(sys.version)"
& 'D:\software\Anaconda\Scripts\conda.exe' run -n labmeeting-ai python -B -m pip check
```

**通过条件：** 解释器属于选定的真实Conda环境，主要包与环境文件匹配；`pip check`无依赖冲突。它不证明GPU已能推理。

**仅环境不存在、且已获安装批准时：**

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' env create -f 'E:\BRC\Meet\LabMeeting-AI\environment.yml'
```

来源为conda-forge，以及YAML中 `pip:` 部分对应的PyPI发行包。创建后重新核对解释器和 `pip check`。同名环境存在但损坏或缺包时，列出差异和针对性修复方案；不要删除环境、重装全部依赖或安装未锁定的最新版本。当前脚本应由独立Conda子进程执行，不导入宿主软件自己的Python进程。

## 3. 检查并准备 GPU 运行库

`environment.yml`不保证包含完整GPU DLL。转写代码使用 `device="cuda"`，没有CPU回退；需要兼容NVIDIA GPU/驱动、CUDA12 runtime、cuBLAS/cuBLASLt和cuDNN9组件。

```powershell
nvidia-smi
Get-ChildItem -LiteralPath 'D:\software\Anaconda\envs\DL\Lib\site-packages\torch\lib' -File | Where-Object { $_.Name -match '^(cudart|cublas|cudnn)' } | Select-Object Name
& 'D:\software\Anaconda\Scripts\conda.exe' run -n labmeeting-ai python -B 'E:\BRC\Meet\LabMeeting-AI\labmeeting.py' check --dll-dir 'D:\software\Anaconda\envs\DL\Lib\site-packages\torch\lib'
```

主要文件包括 `cudart64_12.dll`、`cublas64_12.dll`、`cublasLt64_12.dll`、`cudnn64_9.dll` 和配套 `cudnn_*64_9.dll`。本机复用已有CUDA12.4/cuDNN9.1.0.70目录；PyTorch和名为 `DL` 的环境不是必装依赖，不要为了复制路径而新装它们。若组件在不同目录，可多次传 `--dll-dir`；仅影响子进程，不改系统PATH。

**通过条件：** DLL目录实际存在，`check`中的主要包版本不为null，CUDA设备可见并支持选定计算类型。仍需第5步实际推理验证。

**缺运行库时：** 先寻找用户已安装的兼容组件。新电脑可评估下面的Conda候选方案，先查看求解计划：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' install -n labmeeting-ai --override-channels -c conda-forge 'cuda-version=12.4' 'cuda-cudart=12.4.127' 'libcublas=12.4.5.8' 'cudnn=9.3.0.75' --dry-run
```

这些win-64包及CUDA12依赖已核对元数据，**该新机组合未在本机安装或完成推理验证**，不能冒充现有基线。审阅计划并获批准后，才执行对应实际安装：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' install -n labmeeting-ai --override-channels -c conda-forge 'cuda-version=12.4' 'cuda-cudart=12.4.127' 'libcublas=12.4.5.8' 'cudnn=9.3.0.75' -y
```

安装后核对实际DLL位置，通常在 `D:\software\Anaconda\envs\labmeeting-ai\Library\bin`，用该路径替换后续 `--dll-dir`，再执行检测和短测。求解失败时报告冲突，不自动升级驱动或切换CUDA大版本。Microsoft C++ runtime若缺失，参考 [Microsoft官方说明](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)，按授权安装；不因普通弃用警告而重复安装运行库。

## 4. 检查并下载 ASR 模型

模型不是训练数据集。无需另下语音标注、声纹、科研数据或字幕；Silero VAD随faster-whisper包提供。转写与总结也不需要额外的OpenAI/DeepSeek SDK、本地总结LLM、WhisperX或pyannote。

固定模型为 `dropbox-dash/faster-whisper-large-v3-turbo` 的CTranslate2版本，revision `0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf`。五个配套文件为：

```text
models/large-v3-turbo/
├── model.bin                  1,617,884,929字节，约1.62GB
├── config.json                模型结构
├── preprocessor_config.json   音频特征配置
├── tokenizer.json             分词器
├── vocabulary.json            配套词表
└── provenance.json            下载器生成的本地来源与哈希记录
```

**已有可信模型：** 检查文件和来源；不要重新下载。来源不明、缺文件或完整性可疑时先核验，不能把不完整模型当作可用资产。入口硬性检查权重、结构、预处理和分词器四个文件；下载器另保存词表及来源记录。

**首次下载前：** 项目必须已有用户预建的 `tmp`；下载器不支持自动创建缺失的根 `tmp`。若缺失，按用户规则请其准备。下载缓存会写入 `tmp/model-download`，模型最终写入 `models/large-v3-turbo`；分段、合并、复制会暂存多份权重，建议预留约6GB模型/缓存空间，Conda另计。若用户连安装缓存也不允许，说明当前下载器边界后等待调整，不能宣称安装也完全无临时文件。

在已获下载授权且目标模型目录为空或不存在时，从官方来源下载：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' run --no-capture-output -n labmeeting-ai python -B 'E:\BRC\Meet\LabMeeting-AI\download_model.py' --revision '0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf' --expected-model-sha256 'e76620f83d5f5b69efd3d87e3dc180c1bd21df9fbebacfd4335e5e1efcc018da'
```

官方连接不可用时，可改用经过核验的传输路径，二选一，不并行重复下载同一权重：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' run --no-capture-output -n labmeeting-ai python -B 'E:\BRC\Meet\LabMeeting-AI\download_model.py' --revision '0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf' --endpoint 'https://hf-mirror.com' --direct --weight-url 'https://modelscope.cn/models/pengzhendong/faster-whisper-large-v3-turbo/resolve/c312f538745ce1237d0b0c8eef0b81d91ea1fce6/model.bin' --expected-model-sha256 'e76620f83d5f5b69efd3d87e3dc180c1bd21df9fbebacfd4335e5e1efcc018da'
```

默认目标是下载器所在项目的 `models/large-v3-turbo`，不随shell当前目录变化。该模型公开下载不要求HF Token。`hf-mirror.com`是第三方路径；ModelScope只传输同一权重，不混入其不同版本的配置。`--direct`仅忽略该进程环境代理，不关闭TLS。官方SHA256可在 [固定版本文件页](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo/blob/0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf/model.bin)核对。

**通过条件：** 下载器成功退出、完整权重哈希通过、核心文件齐全、`provenance.json`可读。失败时报告具体阶段；目标非空或不完整时，不擅自删除或覆盖原权重。按授权修复或选择项目内新的 `--model-dir`，并同步转写参数。正常会议的 `stream`只读本地模型，缺文件不会联网补齐。

下载成功后，仅清理本次任务已确认可重建的安装缓存，并遵守用户清理权限；不得删除 `tmp`目录本身、其他来源数据或最终模型。已有模型的日常使用无需再进入本步骤。

## 5. 实际 GPU 短测与返回日常流程

使用用户提供、允许读取的视频，短测仅截取开头到指定时长，不另存音频或测试片段。以下DLL路径须按第3步核实：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' run --no-capture-output -n labmeeting-ai python -B 'E:\BRC\Meet\LabMeeting-AI\labmeeting.py' stream --video '用户视频的实际完整路径.mp4' --model 'E:\BRC\Meet\LabMeeting-AI\models\large-v3-turbo' --dll-dir 'D:\software\Anaconda\envs\DL\Lib\site-packages\torch\lib' --limit-seconds 120
```

**通过条件：** 进程exit0，完整收到 `segments` 及最终 `complete`；段数一致，`scope="limited"`、`limit_seconds=120`，处理音频时长不超过所选范围及实际音轨。开头静音时可延长限制以覆盖发言；无语音不等于GPU故障。短测不能作为整场结果或每小时五分钟的性能证明。

显存不足时先报告占用，评估batch1；不自动关闭其他软件、不转CPU或更换模型。程序已设置进程内MKL顺序模式及关闭CUDA编译缓存，不用宿主手动修改系统环境。仍有运行库错误时保留错误文本于会话，核对版本与DLL来源，不启用忽略重复运行库的开关。

全部条件通过后回到 `SKILL.md`，正式运行时去掉 `--limit-seconds`，不再重复安装、下载和短测。用到的所有命令、错误与核验结果在会话中报告，不生成额外日志或进度文档。
