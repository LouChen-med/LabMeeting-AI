## CUDA 与环境

CTranslate2 4.5 的[官方发布说明](https://github.com/OpenNMT/CTranslate2/releases/tag/v4.5.0)明确切换至 cuDNN 9，不能继续套用 cuDNN 8 安装建议。应锁定实际包版本，核对环境内 DLL，完成 GPU 推理后再认定兼容；`nvidia-smi` 显示的 CUDA 版本不等于本机已安装相同版本的 Toolkit。优先复用已存在且兼容的运行库，不改系统 PATH 或升级驱动来迎合未经测试的依赖组合。

CTranslate2 4.6.0 的 [Windows 初始化代码](https://github.com/OpenNMT/CTranslate2/blob/v4.6.0/python/ctranslate2/__init__.py)依赖 `pkg_resources`，而 [Setuptools 82 发布记录](https://setuptools.pypa.io/en/latest/history.html#v82-0-0)已移除此模块；当前环境配置因此约束 `setuptools<82`。

本机 `labmeeting-ai` 已安装 Python 3.11.18、PyAV 18.1.0、NumPy 2.4.6、Pillow 13.0.0、faster-whisper 1.2.1、CTranslate2 4.6.0、huggingface-hub 0.36.2、ONNX Runtime 1.31.1；`pip check` 通过。已实际完成 GPU 内存转写、定点内存提帧及当前 agent 写出纪要的完整流程，使用 `int8_float16`、batch 2、beam 1。本机的 cuBLAS/CUDA12/cuDNN9 由既有 DL 环境的 `torch/lib` 提供，仅在进程中读取；`environment.yml` 本身不包含这些 GPU DLL，其他电脑须单独核实并提供兼容运行库。

本机 NumPy 的 MKL 与转写依赖曾发生 OpenMP 运行库冲突。程序在依赖导入前设置当前进程的 `MKL_THREADING_LAYER=SEQUENTIAL`，采用 [Intel 官方支持的顺序执行模式](https://www.intel.com/content/www/us/en/docs/onemkl/developer-guide-windows/2023-0/call-onemkl-functions-from-multi-threaded-apps.html)解决；未使用忽略重复运行库错误的开关，未修改系统环境或其他 Conda 环境。

## 日常启动与文件写入边界

本机 `conda run`经源码核对会先写临时批处理再删除，`--no-capture-output`不关闭这一行为。因此日常 `stream`、`frame-inline`、`metadata`、`check`和单元测试改用已核实的 `D:\software\Anaconda\envs\labmeeting-ai\python.exe -I -B -u -X utf8`；环境仍由Conda管理。Skill自带固定 `scripts/run.cmd`作为推荐调用入口，透传完整CLI参数且不生成临时批处理；直接解释器是等价备用。`-I`隔离用户site和 `PYTHONPATH`，`-B`禁用字节码写盘，`-u`实时输出，`-X utf8`固定UTF-8。主入口在本进程加载 `sys.prefix\Library\bin`，GPU组件通过 `--dll-dir`提供，不依赖 `activate`。

整合后的Skill在 `scripts/`内包含完整 `labmeeting.py`和 `download_model.py`，环境配置只位于Skill根的 `environment.yml`；完整文件夹可独立分发源码，无需另外克隆完整项目。固定入口始终调用同目录的 `labmeeting.py`，支持进程级 `LABMEETING_AI_PYTHON`。模型和安装缓存仍可复用原位置；Conda环境、GPU运行库与模型不随Skill打包。

入口尽早禁用Python字节码/CUDA缓存、启用HF离线模式，并在依赖导入前安装Python audit hook拦截文件写入尝试；触发即失败，不用先写再删。该防护覆盖Python层，不涵盖未暴露audit事件的原生DLL写入，单位测试不替代真实短测和目录监控。宿主不得另存转写、截图或使用磁盘spool；脚本不能控制AI应用自身会话数据库和系统分页，故不承诺整个操作系统无写入。

最终正文在内存中准备好后直接写用户指定MD，目标不存在时独占创建；不写临时稿、不使用原子写入临时副本，文件工具也不得暗自写备份。结束时检查无残留只作补充，不能据此证明处理时从未写入。完整宿主适配要求见[工具调用协议](工具调用协议.md)。

整合前固定入口与默认设置的历史实测：通过 `cmd.exe /d /s /c`调用 `scripts/run.cmd`，`check`退出0、耗时1.391秒；默认auto转写120秒音频得到3段，耗时9.843秒，完成设置为 `multilingual=true`、`task=transcribe`；300秒时点内存取帧得到60,974字节JPEG，耗时1.261秒。三步均退出0，未触发Python写入拦截。6处根目录的FileSystemWatcher监控中，项目、视频、环境、`.cache`及NVIDIA缓存目录零事件；系统TEMP有50个事件，因存在并发活动且监控不含PID，无法归因，不能表述为全机或TEMP零写入。这是当时所测调用、片段与目录的观察结果，不证明所有原生路径永久无写入，也不代替整合后入口的验证。

## 中英文混合输入

默认 `--language auto`映射 `language=None`、`multilingual=True`、`task=transcribe`，保留原语言，每个VAD音频块（约30秒）选择主语言提示；支持中英文交替，不是逐词或每条最终字幕段的语言检测。同一块内的混合术语仍需复核。`--language zh`/`en`固定提示并关闭分块切换，均不翻译。`complete.language`是初始检测结果，`settings.language_mode`、`multilingual`、`task`另行记录模式。纪要用中文撰写，保留有依据的英文专业术语、缩写和名称原文。

整合前7项单位测试通过，覆盖中英文本原样保留、auto/zh/en模式选择和9类文件变更前拦截。混合语言行为由模拟API/文本保留测试验证，真实短测内容为中文，尚未评估中英文人工标注识别准确率，不能据此承诺混合语音的准确率。

## 首次模型下载与完整性

`download_model.py` 属于一次性工具安装流程，不是会议处理入口；正常总结只读取已有模型。脚本拒绝覆盖非空模型目录，首次下载仍须遵守安装与文件写入授权。需要重新搭建时先检查 `download_model.py --help`，可显式指定官方 endpoint；网络受限时可选择下列已实测路径，并透明记录来源：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' run --no-capture-output -n labmeeting-ai python -B 'E:\BRC\Meet\LabMeeting-AI\.agents\skills\lab-meeting-summary\scripts\download_model.py' --project-dir 'E:\BRC\Meet\LabMeeting-AI' --repo 'dropbox-dash/faster-whisper-large-v3-turbo' --revision '0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf' --endpoint 'https://hf-mirror.com' --direct --weight-url 'https://modelscope.cn/models/pengzhendong/faster-whisper-large-v3-turbo/resolve/c312f538745ce1237d0b0c8eef0b81d91ea1fce6/model.bin' --expected-model-sha256 'e76620f83d5f5b69efd3d87e3dc180c1bd21df9fbebacfd4335e5e1efcc018da'
```

`hf-mirror.com` 是第三方访问路径，不能称为官方镜像。上例的小配置文件固定在 HF revision，ModelScope 只作为同一权重的传输源；权重大小为 1,617,884,929 字节，完整 SHA256 已与 [HF 官方固定修订文件页](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo/blob/0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf/model.bin)核对。未通过完整哈希校验不能使用；不能仅根据文件名或前若干字节认定一致。显式 `--direct` 只让该下载进程忽略环境代理，不修改系统代理，也不关闭 TLS。

一次性模型下载器的可恢复下载缓存不是会议中间资料。内置下载器以 `--project-dir`指定安装资产根，未指定默认Skill根。未指定 `--model-dir`时为资产根下的 `models/large-v3-turbo`，相对路径也基于资产根解释，且不能越出资产根；缓存为资产根的 `tmp/model-download`。资产根必须已有用户预建的 `tmp`，不自动创建。上例显式复用本机项目资产根，换机须替换Skill及资产路径；已有模型不需要重新下载或迁移。若用户要求连工具安装缓存也不得写盘，先说明这一实现边界，不能伪称该下载器完全无临时文件。模型准备完毕后，会议的 `stream`、`frame-inline` 无需 `--project-dir`或 `--work-dir`，不调用下载器。

本节保留的 `conda run`只用于首次模型安装/下载；其临时启动文件和安装缓存须纳入安装授权，不得将此命令套用到读取真实会议的日常处理或短测。

## 性能证据的边界

faster-whisper 官方基准在 RTX 3070 Ti 8 GB、CUDA 12.4 上，对 13 分钟音频使用 large-v2、beam 5、batch 8，列出 FP16 17 秒和 INT8 16 秒。这是 ASR 测试，不能直接推断其他 GPU、中文科研会议或包含 agent 总结的端到端耗时。速度目标需要在实际视频上完整计时；阶段耗时与完整耗时在 stdout 或回复中报告，不额外写计时记录文件。

本机一次完整实测：约150分钟录屏（其中会议内容约105分钟），内存音频解码78.385秒、模型加载5.128秒、ASR 211.343秒，本地处理总计295.999秒。从完整处理开始，计入 agent 全文阅读、关键帧复核、撰写和核验最终MD，合计679秒，按完整录像长度折算约271秒/小时。首次环境搭建、模型下载及后续Git发布不计入。该次材料达到目标，不代表不同语速、噪声、有效内容比例或硬件占用的所有一小时录像均能在五分钟内完成；不得将阶段耗时冒充端到端保证。

该历史记录用于说明速度，不替代固定入口、语言模式和写入防护的验证；整合前短测范围与结果见上文，120秒短测不能作为整场端到端速度证明，整合后的本次检查结果另行报告。

## 与早期方案的差异

早期选择包含 WhisperX、说话人分离及可切换的 Codex/DeepSeek 总结。当前优先落实 Windows/Conda、速度目标及“仅保存最终 MD”：`stream` 在内存解码并转写，按批次将全部分段写到 stdout；当前 agent 完整阅读，再通过 `frame-inline` 按时间在内存取少量 JPEG。工具层解析 base64 后直接渲染图片，不打印大段 base64、不落地截图。该路线取代早期先写 WAV、JSON/SRT、分段文本和图片的处理方式。

由正在工作的 Codex 或 DeepSeek Harness 完成语义总结，避免额外本地 LLM、第二套操作系统或不必要的 API 适配层。两种 agent 均可遵循此技能，不表示已实现两个可程序化调用的独立后端。

快速路线不能冒充已完成词级对齐或自动说话人分离。按汇报段落组织纪要与技术上的 diarization 是不同能力；报告人的身份仍需从口头介绍或画面核实。最终输出只含文字与原视频时间，不嵌图；音频、转写与图片只在内存和本次工具响应中使用，不留本地会议中间资料。
