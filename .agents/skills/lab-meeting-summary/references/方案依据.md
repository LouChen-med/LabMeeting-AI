## CUDA 与环境

CTranslate2 4.5 的[官方发布说明](https://github.com/OpenNMT/CTranslate2/releases/tag/v4.5.0)明确切换至 cuDNN 9，不能继续套用 cuDNN 8 安装建议。应锁定实际包版本，核对环境内 DLL，完成 GPU 推理后再认定兼容；`nvidia-smi` 显示的 CUDA 版本不等于本机已安装相同版本的 Toolkit。优先复用已存在且兼容的运行库，不改系统 PATH 或升级驱动来迎合未经测试的依赖组合。

CTranslate2 4.6.0 的 [Windows 初始化代码](https://github.com/OpenNMT/CTranslate2/blob/v4.6.0/python/ctranslate2/__init__.py)依赖 `pkg_resources`，而 [Setuptools 82 发布记录](https://setuptools.pypa.io/en/latest/history.html#v82-0-0)已移除此模块；当前环境配置因此约束 `setuptools<82`。

本机 `labmeeting-ai` 已安装 Python 3.11.18、PyAV 18.1.0、NumPy 2.4.6、Pillow 13.0.0、faster-whisper 1.2.1、CTranslate2 4.6.0、huggingface-hub 0.36.2、ONNX Runtime 1.31.1；`pip check` 通过。已实际完成 GPU 内存转写、定点内存提帧及当前 agent 写出纪要的完整流程，使用 `int8_float16`、batch 2、beam 1。本机的 cuBLAS/CUDA12/cuDNN9 由既有 DL 环境的 `torch/lib` 提供，仅在进程中读取；`environment.yml` 本身不包含这些 GPU DLL，其他电脑须单独核实并提供兼容运行库。

本机 NumPy 的 MKL 与转写依赖曾发生 OpenMP 运行库冲突。程序在依赖导入前设置当前进程的 `MKL_THREADING_LAYER=SEQUENTIAL`，采用 [Intel 官方支持的顺序执行模式](https://www.intel.com/content/www/us/en/docs/onemkl/developer-guide-windows/2023-0/call-onemkl-functions-from-multi-threaded-apps.html)解决；未使用忽略重复运行库错误的开关，未修改系统环境或其他 Conda 环境。

## 首次模型下载与完整性

`download_model.py` 属于一次性工具安装流程，不是会议处理入口；正常总结只读取已有模型。脚本拒绝覆盖非空模型目录，首次下载仍须遵守安装与文件写入授权。需要重新搭建时先检查 `download_model.py --help`，可显式指定官方 endpoint；网络受限时可选择下列已实测路径，并透明记录来源：

```powershell
& 'D:\software\Anaconda\Scripts\conda.exe' run --no-capture-output -n labmeeting-ai python -B .\download_model.py --repo 'dropbox-dash/faster-whisper-large-v3-turbo' --revision '0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf' --endpoint 'https://hf-mirror.com' --direct --weight-url 'https://modelscope.cn/models/pengzhendong/faster-whisper-large-v3-turbo/resolve/c312f538745ce1237d0b0c8eef0b81d91ea1fce6/model.bin' --expected-model-sha256 'e76620f83d5f5b69efd3d87e3dc180c1bd21df9fbebacfd4335e5e1efcc018da'
```

`hf-mirror.com` 是第三方访问路径，不能称为官方镜像。上例的小配置文件固定在 HF revision，ModelScope 只作为同一权重的传输源；权重大小为 1,617,884,929 字节，完整 SHA256 已与 [HF 官方固定修订文件页](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo/blob/0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf/model.bin)核对。未通过完整哈希校验不能使用；不能仅根据文件名或前若干字节认定一致。显式 `--direct` 只让该下载进程忽略环境代理，不修改系统代理，也不关闭 TLS。

一次性模型下载器的可恢复下载缓存不是会议中间资料；其现有实现要求项目已有 `tmp`。若用户要求连工具安装缓存也不得写盘，先说明这一实现边界，不能伪称该下载器完全无临时文件。模型准备完毕后，会议的 `stream`、`frame-inline` 无需 `--work-dir`，不调用下载器。

## 性能证据的边界

faster-whisper 官方基准在 RTX 3070 Ti 8 GB、CUDA 12.4 上，对 13 分钟音频使用 large-v2、beam 5、batch 8，列出 FP16 17 秒和 INT8 16 秒。这是 ASR 测试，不能直接推断其他 GPU、中文科研会议或包含 agent 总结的端到端耗时。速度目标需要在实际视频上完整计时；阶段耗时与完整耗时在 stdout 或回复中报告，不额外写计时记录文件。

本机一次完整实测：约150分钟录屏（其中会议内容约105分钟），内存音频解码78.385秒、模型加载5.128秒、ASR 211.343秒，本地处理总计295.999秒。从完整处理开始，计入 agent 全文阅读、关键帧复核、撰写和核验最终MD，合计679秒，按完整录像长度折算约271秒/小时。首次环境搭建、模型下载及后续Git发布不计入。该次材料达到目标，不代表不同语速、噪声、有效内容比例或硬件占用的所有一小时录像均能在五分钟内完成；不得将阶段耗时冒充端到端保证。

## 与早期方案的差异

早期选择包含 WhisperX、说话人分离及可切换的 Codex/DeepSeek 总结。当前优先落实 Windows/Conda、速度目标及“仅保存最终 MD”：`stream` 在内存解码并转写，按批次将全部分段写到 stdout；当前 agent 完整阅读，再通过 `frame-inline` 按时间在内存取少量 JPEG。工具层解析 base64 后直接渲染图片，不打印大段 base64、不落地截图。该路线取代早期先写 WAV、JSON/SRT、分段文本和图片的处理方式。

由正在工作的 Codex 或 DeepSeek Harness 完成语义总结，避免额外本地 LLM、第二套操作系统或不必要的 API 适配层。两种 agent 均可遵循此技能，不表示已实现两个可程序化调用的独立后端。

快速路线不能冒充已完成词级对齐或自动说话人分离。按汇报段落组织纪要与技术上的 diarization 是不同能力；报告人的身份仍需从口头介绍或画面核实。最终输出只含文字与原视频时间，不嵌图；音频、转写与图片只在内存和本次工具响应中使用，不留本地会议中间资料。
